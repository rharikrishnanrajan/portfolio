## THE EFFECT (what the owner wants)
As the page scrolls, content blocks spiral into place in 3D, alternating left and right like a spiral staircase (a gentle rotateY/rotateX/translateZ entrance), decorative and hero layers move at different speeds (parallax), a faint logarithmic spiral turns slowly in the background, and cards tilt toward the pointer on hover. It must feel smooth (inertial), never distracting, never blurry once settled, and never break navigation, focus or readability.

## S1. Config and pure math (src/lib/spiral.ts)
- Export one documented `SPIRAL_CONFIG` object so the owner can tune the feel by editing numbers: perspective 1200 (px), entryRotateY 18 (deg), entryRotateX 10 (deg), entryTranslateZ -120 (px), entryTranslateX 40 (px), entryTranslateY 60 (px), entryScaleFrom 0.94, exitRotateY 6 (deg), exitOpacityMin 0.7, entryStart 1.0 (element top at the viewport bottom), entryEnd 0.55 (element top at 55% of the viewport height), exitStart 0.2, lerp 0.12, minViewportWidth 768, parallaxMaxPx 120, tiltMaxDeg 6, backgroundRotatePerPx 0.04 (deg), backgroundScaleMax 0.15.
- Pure functions (all unit-testable, no DOM): `easeOutCubic`, `clamp`, `entryProgress(top, vh)`, `computeSpiral(e, dir, exitAmount)` returning {tx, ty, tz, rx, ry, scale, opacity}, `toTransform(values)` which returns exactly the string "none" when e >= 0.999 and exitAmount is 0, `parallaxOffset(elementCenterY, viewportCenterY, depth, maxPx)`, and `spiralPath(turns, arms, points)` which generates an SVG path string for logarithmic spirals (r = a * e^(b*theta), a about 8, b chosen so the outer radius is about 700 in a 1000x1000 viewBox, 3 arms rotated by 120 degrees, about 240 points per arm, no NaN).
- Math for entry: e_raw = clamp((vh - top) / (vh * (entryStart - entryEnd)), 0, 1), e = easeOutCubic(e_raw); the transform is perspective(P) translate3d(dir*tx*(1-e), ty*(1-e), tz*(1-e)) rotateY(-dir*ry*(1-e)) rotateX(rx*(1-e)) scale(from + (1-from)*e) with opacity = e. Exit only for elements whose bottom is above the viewport by less than one viewport: exitAmount in [0,1] gives rotateY(dir*exitRotateY*exitAmount) and opacity down to exitOpacityMin; farther away elements are left settled.

## S2. Engine (same file or src/lib/spiralEngine.ts)
- `motionEnabled()` returns false when prefers-reduced-motion is reduce, when `document.documentElement.dataset.motion === "reduced"` (set by the motion switch in S8), when navigator.connection?.saveData is true, when the viewport is narrower than minViewportWidth, or when requestAnimationFrame/IntersectionObserver are missing. It re-evaluates on resize and on matchMedia change; when it flips to false every registered element is reset to no transform and full opacity immediately.
- Registration API: `registerSpiral(el, { kind: "block" | "card" | "layer", dir?, depth? })` returning an unregister function. Direction alternates automatically by registration order (+1, -1, ...) unless given. The hook src/hooks/useSpiral.ts and a small `<SpiralBlock>` wrapper component (src/components/SpiralBlock.tsx, props: as, kind, depth, className, children) wrap this and clean up on unmount; re-registering on route changes and on realtime content updates must work without duplicates.
- Measuring: do NOT call getBoundingClientRect every frame. Cache each element's document-space top, height and centre with a helper that sums offsetTop through the offsetParent chain (offsetTop ignores transforms, so measurements stay correct while an element is rotated). Re-measure on window resize, with a ResizeObserver on each registered element and on document.body, after document.fonts.ready, and when images load. Then per frame compute positions from the cached values and the smoothed scroll value.
- Loop: one passive scroll listener stores the target scroll position; one requestAnimationFrame loop smooths it (smooth += (target - smooth) * lerp) and runs ONLY while scrolling or until |target - smooth| < 0.1 px, then stops (no idle loop, no setInterval). Maintain the set of near-viewport elements with a shared IntersectionObserver (rootMargin about 20% beyond the viewport) and update only those. In each frame read first, then write all styles. No allocations or querySelector calls in the hot path.
- Settling: when an element reaches e >= 0.999 remove its inline transform and opacity entirely (so text is crisp and no stacking context stays behind) and remove `will-change`. Set `will-change: transform, opacity` only while an element is actually animating. Use `backface-visibility: hidden` on animating elements.
- Initial state: elements are only hidden (opacity 0) by the engine after it has initialised and measured them, never by static CSS, so no-JS, SSR-like and failed-init cases show everything. Elements already inside the viewport at load start settled. A direct visit to a hash URL (for example /#skills) must not leave anything transformed that is in or above the viewport.
- Focus safety: on focusin inside a spiral element, immediately settle that element (e = 1) so focus scrolling, caret position and autofill are exact. Never transform the contact form container, the navbar, the mobile drawer dialog, or any element containing a focused input: the contact form column only fades.
- Hash navigation safety: apply transforms only to inner wrapper elements, never to the <section> that carries the id and scroll-margin-top, so scrollToSection and scroll-spy still use untransformed layout positions. Verify that scrollToSection in src/lib/scroll.ts does not depend on getBoundingClientRect of a transformed element; if it does, switch it to the cached/offset-based position.
