## F6. Spiral 3D scroll with parallax (smooth, safe, performant)
Goal: as the page scrolls, content spirals into place in 3D (alternating left/right like a spiral staircase), layers move at different speeds (parallax), and everything stays smooth and readable. Implement it as a small, self-contained engine.
- Files: src/lib/spiral.ts (engine), src/hooks/useSpiral.ts (hook/registration), CSS in src/index.css, tests in src/__tests__/spiral.test.ts(x).
- Registration: elements opt in with a data attribute (`data-spiral="block"`, `"card"` or `"layer"`) and an optional `data-depth` number for layers; direction alternates by element index (+1, -1). Apply transforms to INNER wrappers only, never to the <section> that carries the id and scroll-margin-top, so hash navigation and scroll-spy keep using untransformed layout positions.
- Loop: one passive scroll listener records the target scroll position; one requestAnimationFrame loop smooths it (lerp factor about 0.12) and runs ONLY while scrolling or while the smoothed value is still converging, then stops (no idle loop). Track which registered elements are near the viewport with a shared IntersectionObserver (generous rootMargin) and update only those. In each frame read all rects first, then write all styles (no layout thrashing).
- Entry effect (progress e from 0 to 1 as the element moves from the viewport bottom to about 40% of the viewport height, eased): transform: perspective(1200px) translate3d(dir*40px*(1-e), 60px*(1-e), -120px*(1-e)) rotateY(dir*-18deg*(1-e)) rotateX(10deg*(1-e)) scale(0.94 + 0.06*e), opacity from 0 to 1. At e >= 0.999 remove the inline transform entirely (set to none) and drop will-change, so settled text is crisp and no stacking context is left behind. Optional gentle exit for elements above the viewport: rotateY(dir*6deg) and opacity down to 0.7 at most, never unreadable.
- Parallax layers: hero ghost word, floating chips, the glow behind the avatar and decorative orbs use translate3d(0, scrollY * depth, 0) with small depths (about 0.08 to 0.3), clamped so they never leave their section; the hero avatar and name stay still apart from the existing entrance.
- Decorative spiral background: one fixed, aria-hidden, pointer-events none SVG of a logarithmic spiral (generate the path in code with r = a*e^(b*theta), a few turns, accent stroke at 6-8% opacity) behind the content (z-index below content). It rotates slowly with scroll (transform: rotate(scrollY * 0.04deg) plus a slight scale), through the same smoothed value. No layout shift, no horizontal overflow (use `overflow-x: clip` on html/body, never hidden, so sticky elements keep working).
- Pointer tilt for hover-capable devices only (`(hover: hover) and (pointer: fine)`): project cover, skill cells and about cards tilt up to 6 degrees toward the pointer (rotateX/rotateY with perspective), requestAnimationFrame-throttled, reset smoothly on leave, transform only.
- Safety and gating: one `motionEnabled()` function returns false when prefers-reduced-motion is reduce, the owner's motion switch is off (F8), navigator.connection.saveData is true, or the viewport is narrower than 768 px (below that use only the existing fade-up reveal). When disabled nothing is transformed and everything is visible. Never apply 3D transforms to the contact form container (fade only), the navbar, the drawer dialog or any element that contains a focused input. Print styles show everything. No spiral transform is active when the observer or rAF is unavailable.
- Do not apply useReveal and spiral transforms to the same element; spiral wrappers replace the fade-up for blocks and cards, useReveal remains for small items.
- Smoothness target: 60 fps on a mid-range laptop; verify the logic stays cheap (no per-frame allocations in hot paths, no querySelector in the loop, listeners cleaned up on unmount).
- Tests: progress-to-transform math (e=0 gives the maximum offsets, e=1 gives "none"), alternating direction, the loop stops when converged and restarts on scroll, gating (reduced motion, switch off, saveData, narrow viewport) leaves elements untouched and visible, the contact form is excluded, cleanup removes listeners, and that sections keep their ids untransformed.
